## 一、通用排障纪律

1. **HTTPS 问题先画信任链地图**：系统 CA、Firefox NSS、Chrome/CEF NSS、应用自带 CA，各是各的。
2. **HSTS 站点不要指望"忽略警告"**；要么信任根证书，要么换路径。
3. **`certutil` 版本会影响兼容性**；必要时用旧 NSS 的独立二进制，不要降级系统库。
4. **改动启动方式后验证 `/proc/<pid>/environ`**，不要只看 `.desktop` 文件。
5. **应用内"重启"通常不重新读环境变量**；要完全退出再启动。
6. **同版本不同打包可能行为不同**；先换包，再调参。
7. **软件渲染仍复现 → 不要继续在 GPU 光栅化上打转**，查呈现/帧同步。
8. **一次只改一个变量**，并记录结果；试错矩阵就是靠这个避免"全上但不知道哪个有用"。
9. **全局 CSS/主题补丁必须可还原**，且应用更新会覆盖；不要把它当长期方案。
10. **清理时先 `command -v`**，防止 `~/.local/bin` 的 wrapper 遮蔽 `/usr/bin`。
11. **保留用户数据**（`~/.dsh`、`~/.local/share/dsh-tauri`），只删可再生的启动器和缓存。
12. **inotify 上限**是 DSH 日志明确建议的稳定性修复；大量文件监听场景容易触发 ENOSPC。
13. **插件安装失败要看 pnpm 的 build-script 策略**；`ERR_PNPM_IGNORED_BUILDS` 会让整条安装命令失败。
14. **不要把 MITM 根证书扩散**；它是本机排障工具，不是"系统必备证书"。
15. **所有操作留备份**：`cert9.db`、`~/.pki/nssdb`、`.store.dat`、profile 的 `package.json`。
16. **图标空白先分层**：`_NET_WM_ICON`（窗口）→ desktop entry / `StartupWMClass`（关联）→ GIcon 纹理缓存（Shell）；换新图标名通常比覆盖同名文件更快生效。

## 二、2026-10-24 这次的新教训

### 1. 并发问题必须用并发测试验证——这是本次最贵的一课

**症状**：Steam 里点「开始游戏」，有时能进、有时 2 秒退出，报

```
pressure-vessel-wrap: E: Unable to create symlink ".../var/tmp-XXXX/usr": No such file or directory
```

**我的错**：先怀疑挂载参数（`acl`/`umask`/`dmask`/`fmask` 试了三套），又用**单线程**连做 120 次符号链接测试——全过，于是宣布"NTFS 稳定了"，把工具搬回 NTFS，结果下一次启动又挂。

**真相**：同一挂载点、同一目录

| 测试 | 结果 |
| --- | --- |
| 单线程 100 次 `ln -s` | 0 失败 |
| 8 进程并发 × 40 次 | **192 失败** |

pressure-vessel 正是**多线程并发**创建 `usr/etc/ssl/certs/*` 的链接。测试方式和真实负载不同，测了等于没测。

**以后的做法**：只要怀疑"时序/并发/偶发"，测试要复刻并发度（`xargs -P`、多进程池），并且**多跑几轮**；单线程通过不能作为结论。

### 2. "能跑一次"≠"稳定"，更≠"修好了"

12:46 那次游戏跑了 3 分半，我据此认为修好了；实际上是恰好赶上并发没撞上失败的窗口。**验收标准要写清楚**：跑多久、启动几次、失败率多少。

### 3. 报错信息里的路径是"结果"，不是"原因"

报错指向 `usr/etc/ssl/certs/xxx.pem` 建不出来，看起来像证书问题；真因是底层文件系统在并发下创建 reparse point 失败。**看报错要往下钻一层**：这个操作是在哪个文件系统、什么并发度、什么驱动下做的。

### 4. 系统级改动要区分"持久"和"会话级"

- `/run` 是 tmpfs：`/run/media/$USER/X` 只在当前登录会话存在，**重启就没了**。
- 把 Steam 库路径指向它 → 重启后库直接"消失"（真发生过，18 个游戏全部变未安装）。
- 正确做法：路径放在**开机就存在的真实挂载点**（`/mnt/...`，由 systemd 按 fstab 挂载），并只用**一个**挂载点。

### 5. 一个文件系统问题，先分清"驱动"和"参数"

- `ntfs3`（内核态）：快，但本机并发建符号链接会成片失败。
- `ntfs-3g`（FUSE）：并发稳定，代价是 CPU 开销与元数据变慢。
- 挂载参数（`acl`/`umask`/`dmask`）在这件事上完全是噪声——**换驱动才是解**。

判断顺序应该是：**驱动 → 并发度 → 参数**，而不是从参数开始穷举。

### 6. root 权限要按次授权，不要一把梭

- 这台机器 `sudo` 需要密码且不缓存（`tty_tickets`），`/run/sudo/ts` 都不存在；
- `pkexec <命令>` 会弹 polkit 密码框，**每次都要输一次**，不缓存；
- 所以正确姿势是：**把整套操作写成一个脚本，用 `pkexec bash 脚本` 一次授权跑完**；
- 想省事可以配 `NOPASSWD`，但只放行最小命令集（`mount`/`umount`/`ntfsfix`），**绝不能写 `ALL` 或 `/bin/bash`**。

### 7. Wayland 的能力边界要提前确认

- 外部进程**无法最小化**别人的窗口（没有 `wlr-foreign-toplevel` 之类接口），`xdotool` 只对 XWayland 有效 → 想做"窗口收纳"只能写 GNOME Shell 扩展。
- 原生 Wayland 窗口的 `app_id` **晚于 `window-created` 提交**（创建瞬间是空名）→ 匹配必须靠 `pid` 兜底 + 周期扫描。
- 应用自己会把窗口顶回来（QQ 自动登录后连顶 3~4 次）→ "有焦点就让位"不能当通用规则，需要**宽限期**：刚压下去的一段时间内无视焦点。

### 8. 取舍要说清代价，而不是只说"能用"

这次为了不占内部盘，最终选了 `ntfs-3g`。它不是免费的：

| 代价 | 实测/说明 |
| --- | --- |
| CPU | 直读 351 MB 时 `ntfs-3g` 自己吃掉 190 ms CPU（约 46% 单核） |
| 元数据 | 建 1500 个小文件 0.33 ms/个（ext4 约 0.03 ms/个，不同盘仅供参考） |
| 预分配 | 不支持 `fallocate`，大更新可能更慢 |
| 单点 | 用户态进程崩了 → 挂载点所有 IO 报 EIO，需要重挂 |
| 安全副作用 | 卷带 dirty 标记时**拒绝 rw 挂载**，需 `ntfsfix`/chkdsk |

顺读带宽基本无损（`ntfs3` 509 MB/s vs `ntfs-3g` 505 MB/s，direct IO）。**结论：为了 Proton 能稳定启动，这个代价可以接受；但必须写下来，别装成没成本。**

### 9. 用户约束要尽早问清楚

中途我做了 7 G 的"迁移到内部盘"方案，用户明确拒绝（内部盘空间不紧不窄）。正确顺序是：**先确认硬约束**（空间、路径、是否双系统），再选方案。最后 2.4 G 折中方案和 ntfs-3g 方案都是在"不占内部盘"的前提下才成立。

## 三、我这次犯过的错（比结论更有价值）

1. **三次把"路径/挂载参数"当根因**：`/run/media` 与 `/mnt` 的差别、`acl`/`umask` 的差别，都不是原因；真正的原因是驱动层的并发缺陷。
2. **用单线程测试给并发问题下结论**：导致白搬一次 2.4 G 文件、白失败一次启动。
3. **没先确认空间约束就动手迁移**：方案本身可用，但不符合用户约束，最后完整回滚（好在脚本幂等、有备份）。
4. **"有焦点就让位"当通用规则**：QQ 自动登录顶窗口时窗口自带焦点 → 被误判成"用户手动还原"，于是窗口留在桌面上。
5. **误删过一次扩展源码**：清理未采用的网格扩展时连带删了 `quiet-startup`，靠下一个提交恢复。教训：删除前先 `git status` 看清范围。

## 四、可复用的检查顺序（遇到新问题先走这一遍）

1. **先读日志**：`compat_log.txt`（Steam 兼容性）、`console-linux.txt`（容器/Proton）、`Player.log`（Unity）、`/tmp/quiet-startup.log`（扩展）、`journalctl -b`（系统）。
2. **确认环境事实**，别猜：`findmnt`（挂载与驱动）、`stat -c %d`（是不是同一个超级块）、`/proc/<pid>/environ`（参数是否真的生效）。
3. **复现最小化**，然后**按真实并发度放大**（单线程 → 多进程）。
4. **做对照实验**：同一文件、同一硬件、同一直读模式，只改一个变量。
5. **固化**：写成幂等脚本（`--dry-run`、备份、验证步骤），别只留一条命令。
6. **记录**：把"哪些方向试错了"写进文档，它的价值不小于最终方案。
