# G1 盘开机自动挂载：从 udisks 的临时挂载到 fstab，以及 ntfs3 / ntfs-3g 怎么选

> 返回索引：[README](../README.md) ｜ 相关：第 9 篇（Steam / Proton 在 NTFS 库上失败）、第 16 篇（Windows 分区只读挂载）｜ 相关脚本：`../scripts/switch-g1-to-ntfs3g.sh`、`../scripts/move-proton-app-to-ext4.sh`

**一句话结论**：G1（`/dev/sda2`，NTFS，931 GB）用 **fstab + ntfs-3g** 固定挂到 `/mnt/G1`，带 `nofail` 防卡启动；**不要**让 udisks 再挂一份到 `/run/media/...`。

---

## 1. 为什么不能就这么用

插着 G1 登录后，GNOME 会自动把它挂到 `/run/media/qys/G1`。看着能用，但对「放 Steam 库」这件事有三个硬伤：

| 问题 | 后果 |
|---|---|
| `/run` 是 **tmpfs**，重启就没了 | 下次开机得重新插盘/点一下才挂上；如果 Steam 先启动，库就是"离线"状态 |
| 挂载点带**用户名** | 换用户、改用户名，路径就变；脚本、快捷方式、Steam 库记录全部失效 |
| udisks 不给加参数 | `uid/gid/umask/x-gvfs-name` 这类想加加不上，权限和显示名都不受控 |

所以目标很明确：**开机就挂、路径固定、参数可控**。这三件事只有 fstab（或等价的 systemd `.mount`）能给。

## 2. 最终状态

`/etc/fstab`：

```
# G1 (NTFS, 开机自动挂载) — added 2026-10-24
UUID=26D4A177D4A14A3F   /mnt/G1   ntfs-3g   defaults,nofail,uid=1000,gid=1000,umask=022,iocharset=utf8,x-gvfs-show,x-gvfs-name=G1,x-systemd.device-timeout=10   0   0
```

重启后的实测：

```text
$ findmnt -rn -S /dev/sda2 -o TARGET,FSTYPE,OPTIONS
/mnt/G1  fuseblk  rw,relatime,user_id=0,group_id=0,default_permissions,allow_other,...,x-gvfs-show,x-gvfs-name=G1

$ ls -ld /mnt/G1
drwxr-xr-x+ 1 qys qys 8192 ... /mnt/G1          # 所有者是 qys，写入实测通过

$ systemctl status mnt-G1.mount --no-pager | head -3
● mnt-G1.mount - /mnt/G1
     Loaded: loaded (/etc/fstab; generated)
     Active: active (mounted) since ...
```

注意 `FSTYPE` 是 **`fuseblk`** 而不是 `ntfs3` —— 这就是"实际生效驱动是 ntfs-3g"的铁证（见第 6 节）。

## 3. 怎么改（六步，每步都有验证）

> 需要 root。这台机器 `sudo` 要交互密码，把下面六步写成一个脚本再 `sudo bash` 执行，比一条条敲省事。

### 第 1 步：确认设备身份（不要用 `/dev/sdX`）

```bash
lsblk -o NAME,SIZE,FSTYPE,LABEL,UUID,MOUNTPOINTS | grep -A2 sda
# 期望看到 sda2  LABEL=G1  UUID=26D4A177D4A14A3F  ntfs
```

`/dev/sda` 的顺序在加硬盘、改 BIOS 后可能变，**fstab 里必须写 UUID**。

### 第 2 步：备份 fstab

```bash
sudo cp -a /etc/fstab "/etc/fstab.bak-$(date +%Y%m%d-%H%M%S)"
```

这不是形式主义：fstab 写错会在开机时掉进 emergency shell，有备份至少能救援。

### 第 3 步：建挂载点并写条目

```bash
sudo mkdir -p /mnt/G1
# 用编辑器追加第 2 节那一行，或者：
echo 'UUID=26D4A177D4A14A3F /mnt/G1 ntfs-3g defaults,nofail,uid=1000,gid=1000,umask=022,iocharset=utf8,x-gvfs-show,x-gvfs-name=G1,x-systemd.device-timeout=10 0 0' | sudo tee -a /etc/fstab
```

### 第 4 步：让 systemd 重新生成挂载单元

```bash
sudo systemctl daemon-reload
systemctl cat mnt-G1.mount | head -5     # 应看到 generated by systemd-fstab-generator
```

### 第 5 步：先卸掉 udisks 那份，再按 fstab 挂

```bash
# 如果盘现在挂在 /run/media/$USER/G1
sudo umount /run/media/$USER/G1        # 报 busy 见第 5 节
sudo mount /mnt/G1
findmnt -rn -S /dev/sda2 -o TARGET,FSTYPE
```

> **不卸旧的就直接 `mount /mnt/G1` 也能成功**——Linux 允许同一设备挂多处。但那就留下了"双挂载"，见下一节。

### 第 6 步：验证

```bash
findmnt -rn -S /dev/sda2 -o TARGET,FSTYPE,OPTIONS   # 只应有一行
touch /mnt/G1/.write-test && rm /mnt/G1/.write-test  # 普通用户能写
ls /run/media/$USER/ 2>/dev/null                     # 应为空
```

## 4. 每个参数为什么在那

| 参数 | 作用 | 不加会怎样 |
|---|---|---|
| `nofail` | 设备不存在时跳过，不阻塞启动 | 盘没插/坏了 → 开机卡在 emergency shell |
| `x-systemd.device-timeout=10` | 等设备最多 10 秒 | 会按默认 90 秒干等 |
| `uid=1000,gid=1000` | 挂载后归当前用户 | 文件全归 root，普通用户只读甚至不能进 |
| `umask=022` | 文件 644 / 目录 755 | 其他用户可写；或反过来自己写不了（看默认） |
| `iocharset=utf8` | 中文文件名 | 中文变问号/乱码 |
| `x-gvfs-show` | 让「文件」侧栏显示这块盘 | 只能自己 cd 到 `/mnt/G1` |
| `x-gvfs-name=G1` | 侧栏显示的名字 | 显示成 `G1` 以外的名字（默认取标签或路径） |
| 末尾 `0 0` | dump / fsck 顺序 | 对 NTFS 两者都该是 0（fsck 不认 NTFS） |

**不要**加的：`windows_names`。它禁止文件名里出现 `: * ? < > | "`，而 Wine/Proton 必须创建带冒号的文件（比如 `:` 开头的 Steam 前缀文件），加了直接导致游戏启动失败（第 9 篇有完整记录）。

## 5. 坑一：双挂载

### 现象

```text
$ findmnt -S /dev/sda2 -o TARGET,FSTYPE
/run/media/qys/G1   ntfs3
/mnt/G1             ntfs3
```

### 原因

udisks 在你的图形会话登录时先挂了一份（`/run/media/<user>/<label>`），fstab 又挂一份。Linux 不做唯一性约束。

### 影响：比想象的小，但不能不管

- **数据不会分裂**：同一块设备的两次挂载共用同一个超级块（`stat -c %d /mnt/G1 /run/media/qys/G1` 输出同一个数），内核只有一份页缓存，一边写另一边立刻可见。
- **真正的麻烦是"路径不唯一"**：Steam 库里存的绝对路径、你自己写的脚本、快捷方式，都可能指向那条重启就消失的 `/run/media/...`。第 9 篇记录的 Steam 报「兼容性工具失败」就是踩在这上面。
- 少数工具会对同一设备的多挂载做去重/报警，日志会变吵。

### 处理

```bash
# 谁占着？（输出里 f.... 的那一列就是 PID）
sudo fuser -vm /run/media/$USER/G1

# 常见是文件管理器开着那个目录
nautilus -q                                  # 关掉文件窗口
udisksctl unmount -b /dev/sda2               # 不需要 root，因为是"你"挂的
# 或
sudo umount /run/media/$USER/G1
```

`umount: target is busy` 的其它常见来源：某个 shell 的当前目录在里面（`cd` 出去）、Steam 正在用、IDE 在索引。

**最省事的解法：直接重启。** 开机只按 fstab 挂 `/mnt/G1`，udisks 看到设备已挂载就不会再挂第二份。本次就是重启后自愈的。

## 6. 坑二：ntfs3 还是 ntfs-3g

两者都能读写 NTFS，但一个是内核驱动、一个是用户态 FUSE：

| | ntfs3 | ntfs-3g |
|---|---|---|
| 实现位置 | 内核（Linux 5.15+） | FUSE，用户态进程 |
| 挂载后 `findmnt` 显示 | `ntfs3` | `fuseblk` |
| 顺序读写 | 略快 | 略慢 |
| 并发元数据操作 | 弱，出过成片失败 | 稳 |
| Wine/Proton 兼容 | 踩坑多 | 成熟 |
| 加参数 | 内核参数集 | 更多用户态选项（如 `windows_names`） |

### 本机的实测（详见第 9 篇）

- **并发建符号链接**（8 线程 × 40 个）：ntfs3 **192/320 失败**；换 ntfs-3g 后同一测试 **0 失败**。
- **顺序大文件读取**：ntfs3 509 MB/s vs ntfs-3g 505 MB/s——差距可以忽略。
- 结论：这块盘是给 Steam 用的，**选 ntfs-3g**。牺牲约 1% 的吞吐换"Proton 能启动"，非常划算。

### 判断当前用的是哪个

```bash
findmnt -no FSTYPE /mnt/G1     # ntfs3 或 fuseblk
mount | grep sda2              # 更直观：type ntfs3 / type fuseblk
```

**不要看 fstab 里写的类型**——它只是"请求"，内核/工具可能回落到别的驱动（尤其 udisks 那条路径）。这条是这次踩过的：以为改回 ntfs3 了，实际还是 ntfs-3g。

### 想切回 ntfs3

```bash
sudo bash ./scripts/switch-g1-to-ntfs3g.sh   # 脚本方向是 → ntfs-3g
# 反方向：把 fstab 里的 ntfs-3g 改回 ntfs3，卸掉重挂
```

但除非你有明确理由（比如只做大文件拷贝），否则别切回去。

## 7. 坑三：盘不在、卷脏、被 Windows 占着

| 情况 | 表现 | 处理 |
|---|---|---|
| 盘没插 / 坏了 | 无 `nofail` 时开机进 emergency shell | 一定加 `nofail` + `device-timeout` |
| NTFS 被 Windows「快速启动」弄脏 | 挂载报 `The disk contains an unclean file system` | 进 Windows 关快速启动后完整关机，或 `chkdsk C: /f`；**不要**对系统盘 `ntfsfix -d` 硬清（第 16 篇） |
| Windows 还在休眠/占着盘 | 同样报脏 | 先完整关机 |
| 只读挂载系统分区 | `/mnt/win` 用 `ro` | 这是故意的：dirty 卷写进去可能损坏系统（第 16 篇） |

## 8. 排错速查

| 症状 | 最可能原因 | 先看什么 |
|---|---|---|
| 开机卡住/进 emergency | fstab 写错或缺 `nofail` | `systemctl status mnt-G1.mount`、`journalctl -b -u mnt-G1.mount` |
| 挂上了但普通用户不能写 | 缺 `uid/gid/umask` | `ls -ld /mnt/G1`、`findmnt -o OPTIONS` |
| 中文名乱码 | 缺 `iocharset=utf8` | `findmnt -no OPTIONS /mnt/G1` |
| 侧栏看不到 G1 | 缺 `x-gvfs-show` | 同上 |
| 两个挂载点 | udisks 也挂了一份 | `findmnt -S /dev/sda2 -o TARGET` |
| 卸载报 busy | 有进程/目录占用 | `fuser -vm <挂载点>`、`lsof +D <挂载点>` |
| 游戏起不来 | 驱动/路径 | `findmnt -no FSTYPE,SOURCE /mnt/G1`；确认 Steam 库指向 `/mnt/G1/...` |

## 9. 回滚

```bash
# 1) 恢复备份（或手动删掉 UUID=26D4A177D4A14A3F 那一行）
sudo cp /etc/fstab.bak-<时间戳> /etc/fstab
sudo systemctl daemon-reload

# 2) 卸载
sudo umount /mnt/G1

# 3) 可选：删掉空挂载点
sudo rmdir /mnt/G1
```

回滚后行为回到"登录时 udisks 自动挂到 `/run/media/<user>/G1`"，Steam 库路径需要相应改回。

## 10. 经验清单

1. **外置/数据盘进 fstab，第一件事是 UUID + `nofail`**，第二件才是参数。fstab 写错会让机器开不了机，比"没自动挂"严重得多。
2. **`findmnt` 是唯一可信的"现状"**：`findmnt -S <dev> -o TARGET` 看挂载点是否唯一，`-o FSTYPE` 看实际驱动，`-o OPTIONS` 看参数是否生效。别读 fstab 自我安慰。
3. **udisks 与 fstab 会打架**：同一设备两个挂载点不是数据问题，是路径问题；重启是最干净的收尾。
4. **NTFS 给 Proton 用 → ntfs-3g**。ntfs3 在并发建符号链接/元数据操作上不可靠，实测失败率能到 60%；吞吐差距只有个位数百分比。
5. **别加 `windows_names`**：它挡的是 Wine 必须用的冒号文件名，加了游戏直接起不来。
6. **`x-gvfs-show` 这种"用户体验参数"值得加**：不然盘在 `/mnt` 里，文件管理器侧栏看不到，日常用起来很别扭。
